# 第 8 课：工程化——并行、视觉基线、报告附件与 CI

> 前置：第 1–7 课完成。本课示范：`tests/08-ci/01-engineering-demo.spec.ts`；作业：`tests/08-ci/90-homework.spec.ts`。
> 本课调整了 `playwright.config.ts`：显式声明 `expect.timeout`、加 `screenshot: 'only-on-failure'`、`retries` 按 CI 环境区分。

## 1. config 里的工程化开关（本课分支已改）

```ts
use: {
  trace: 'retain-on-failure',
  screenshot: 'only-on-failure',   // 失败自动截屏，随报告/trace 附上
},
expect: { timeout: 5_000 },        // 断言默认超时，显式写出来便于团队对齐
retries: process.env.CI ? 2 : 0,   // CI 自动重试 2 次；本地 0 次——快速反馈
```

- `retries` 的哲学：本地失败立刻看（重试会掩盖不稳定），CI 上重试过滤抖动；**重试通过的用例仍要在报告里标出来**（HTML 报告有 flaky 标记），持续不稳定就该修；
- 全局超时别调大：个别慢场景用单次 `{ timeout }` 覆盖（第 3 课）。

## 2. 视觉基线：toHaveScreenshot

```ts
await expect(page.locator('#login-form')).toHaveScreenshot('login-form.png');
```

- **首次运行**：自动生成基线图（存在 `*.spec.ts-snapshots/` 目录），断言通过；
- **之后每次运行**：与基线像素级比对，不一致即失败；差异确认后用
  `npx playwright test --update-snapshots` 刷新基线（人工确认是「有意的改版」）；
- 基线图**随仓库提交**——它是「页面应该长什么样」的可执行规格；
- 本机（同 WSL 同字体）渲染稳定，跨机器/跨系统对比需用 Docker 镜像保持渲染一致——先知道有这回事。

## 3. serial 模式：有依赖的用例链

```ts
test.describe.configure({ mode: 'serial' });
test('步骤 1：登录并导出 storageState', …);
test('步骤 2：用快照打开已登录上下文', …);
```

serial 模式下用例按顺序跑，**前面失败则后面的自动 skipped**（避免连环误报）。适用「一串强依赖的步骤」；能用独立 context 解决的依赖，优先独立（默认 parallel 更快）。

## 4. 报告附件：testInfo.attach

把运行时的关键信息（环境摘要、失败时的中间数据）挂到报告里，事后排障不用猜：

```ts
test('…', async ({ page }, testInfo) => {
  await testInfo.attach('环境摘要', { body: '…', contentType: 'text/plain' });
});
```

## 5. 多浏览器与 CI（作业方向）

- `projects` 里加 firefox / webkit（先 `npx playwright install firefox webkit`，各约 100MB 下载）；
- GitHub Actions 的 yaml 放 `.github/workflows/`：`npm ci` → `npx playwright install --with-deps` → `npx playwright test` → 上传 HTML 报告为 artifact。本项目没有远端仓库，作业里写好模板即可。
